# ADR-0000: ADRを開発方針の記録として継続更新する

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：全員
- 決定の根拠：ユーザーによるADRの作成・随時更新の指示
- 置き換えるADR：なし
- 後継ADR：なし

## 背景

技術構成・担当分担・画面配置の方針が複数の仕様書に分かれており、選定理由と変更の経緯を追える場所が必要になった。

## 決定

`docs/adr/` に重要な開発方針を記録し、作業に伴う決定・変更時に更新する。作業開始時に一覧と関連ADRを確認するルールをルートのAGENTS.mdに置く。運用は一覧の手順に従う。

## 代替案と理由

会話だけに残すと新しい担当者が経緯を追いにくい。仕様書だけの上書きでは過去の理由が失われるため、現在の仕様と判断履歴を併存させる。

## 影響とトレードオフ

文書更新の手間が増えるため、軽微な変更ごとの新規ADRは不要とする。Acceptedと実装完了を区別し、未検証の技術案はProposedとして扱う。

## 検証・見直し条件

次の重要な方針変更から同じ変更内にADRと仕様更新を含める。運用が重くなった場合は本運用自体も後継ADRで見直す。
