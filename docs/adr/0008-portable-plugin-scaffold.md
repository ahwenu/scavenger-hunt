# ADR-0008: Plugin Extensionsの骨格を移動可能な単独フォルダにまとめる

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：Ahwenu、Plugin Extensions画面は未定（Ahwenu）
- 決定の根拠：ユーザーの「まずPlugin Extensionsの骨格」「後で移動しやすいようにまとめる」という明示指示。Acceptedの対象はこの配置・境界方針であり、実ホスト連携の実証を意味しない
- 置き換えるADR：なし。ADR-0006のplugin骨格段階を具体化
- 後継ADR：なし

## 背景

Sites側のフォルダや共有契約が確定する前にホスト拡張の開発を進める。親のソース、依存、絶対パスへ結合すると、後から移す際にビルドや起動が壊れる。

## 決定

- `plugin/` を依存・lock・起動設定・UI/MCPソース・ビルド/配布スクリプトを含む単独の開発単位にする。Node.js 22以上を前提とする。
- ホストUIは `src/ui/`、MCP/接続は `src/server/`、暫定DTOは `src/shared/contracts.ts` に分ける。React/TypeScript、stdio MCP、MCP Appsブリッジによる骨格を用意する。
- Sitesの共有 `contracts/` が未整備の間は親フォルダをimportしない。正式契約との変換を接続アダプター境界で追加し、契約同期時に両実行面を検証する。
- 未設定時は未接続とし、`KARIMONO_MODE=demo` を選んだときだけサンプル操作を有効にする。デモデータを実際の部屋・参加・得点と扱わない。
- UI/MCPを `dist/` へバンドルし、配布物は必要な宣言・設定・生成物・READMEだけを許可リストで梱包する。秘密値と親の依存を含めない。
- プラグイン登録・公開・Sites/AI実接続・認証の実装は今回の対象外とし、結合時に既存仕様の要件を検証する。

後続作業：独立AI API接続はADR-0010で追加した。ユーザーの追加指示によりローカルPlugin Extensions登録と実表示確認も進める。初期骨格の対象範囲と、後続の登録・表示検証の結果を分けて記録する。

共有用の後続実装では `npm run share` でローカルmarketplace宣言、ビルド済みplugin、INSTALL.mdを一つのアーカイブへまとめ、SHA-256を添える。受取人はNode/Codexの対応環境で展開・登録し、ソース取得やnpm依存のインストールなしで画面を開ける構成にする。秘密設定とAPIサーバーは共有物へ含めず、実AIは各PCのAPI・キー、または将来の公開APIで設定する。

## 代替案と理由

ルートの依存や `contracts/` を直接importする案は実装量が少ないが、移動先に親構成を要求する。先に全体ワークスペースを固定する案はSitesスターターへの制約が増える。今回は自己完結した骨格を先行し、正式接続時にアダプターを移行する。

## 影響とトレードオフ

暫定DTOと将来の正式契約の照合が必要になる。Ahwenuが契約の対応を取りまとめる。デモは画面・MCPの開発補助で、ゲームの正本、採点、永続化を担当するさが さんの実装を置き換えない。担当の正式な割り当てはADR-0002を維持する。

## 検証・見直し条件

最新の確認（2026-10-18）：ユーザーのWork内実Plugin Extensionsでの操作と提供画像2枚により、画面表示・API接続確認・お題「文房具のペンを探そう」の生成表示を1例確認した。条件2つと120秒も表示された。Codexによる直接UI操作の記録とは区別する。写真判定UI・Sitesのゲーム進行・参加者・得点・順位の結合は未検証。

2026-10-18、以下を確認した。

- `npm run check` 成功、`npm test` 6件成功（実MCP結合3件、UI境界3件）。
- `npm run package` で型チェック・ビルド・アーカイブ作成が成功。配布物は宣言・MCP設定・README・MCP/HTMLバンドルだけを含み、ソース・秘密設定・依存・プレビューを含まない。
- `npm run test:portable` 成功。空白を含む一時パスへアーカイブを展開し、`node_modules` のない配布物を無関係な作業ディレクトリから起動。未接続・デモ両モードで8 MCPツールとUIリソースを確認した。
- ソースを空白を含む別パスへコピーし、`node_modules`・`dist`・`artifacts` を持ち込まず `npm ci --ignore-scripts`、型チェック、ビルド、6件のテストが成功した。
- ローカルブラウザプレビューで、stdio MCP経由の部屋作成→お題準備→開始を確認した。

写真判定UI、Sites認証、スマホ参加、得点・順位反映は未検証で、MVP完了条件として残る。

後続のローカル登録では、公式CLIで `karimono-local` marketplaceの登録と `karimono-host` のインストールが成功。一覧の `installed: true`、`enabled: true`、`version: 0.1.0` を確認した。必要な宣言・MCP設定・README・MCP/HTMLバンドルだけを使い、秘密設定は梱包していない。実拡張内の表示・API接続確認・お題生成は、後続のユーザー操作と画像で1例確認した。

インストール済みキャッシュのサーバーへstdio接続し、10ツール、global/threadエントリーポイント、`host_open` の未接続状態、`ai_status` の利用可能応答を確認した。現在のチャットに公開された `host_open` の呼出しも成功。実拡張画面内の表示・操作の確認は継続する。

共有用追加後、`npm run share`、`npm run test:share`、`npm run package`、`npm run test:portable` が成功。共有物のmarketplace・導入手順・SHA-256照合・許可リストと、空白を含む別パス・別cwd・node_modulesなしでの未接続/デモ両モードの10 MCPツール・UIリソースを確認した。型チェックと既存15件のテストも成功。別PCでの実機導入・ローカル配布更新の一連の操作は未実施。

Sitesの共有契約が定まった時点でアダプターを更新する。ホスト側の登録仕様が追加条件を要求した場合は、この配置方針への影響を記録する。Sitesを含む全体の独立ビルドはADR-0006の検証対象のまま。

ADR-0009で既存デモのソースを `apps/cloud/` などへ取り込んだが、今回のpluginはそれらをimportせず、正式な契約への適合・実接続も未検証。デモ取り込みをSitesの直下移行や本番稼働の検証とは扱わない。
