# ADR-0002: 担当者とバックエンド/API処理の責務を分ける

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：Akibako さん、mae さん、さが さん、Ahwenu
- 決定の根拠：ユーザーの担当者指定。詳細な作業境界は対応する初期割り振り
- 置き換えるADR：なし
- 後継ADR：なし

## 背景

バックエンドとAPI処理を別担当にし、画面・外部接続・ゲームルールの重複実装を避ける必要がある。

## 決定

- Akibako さん：スマホ画面のデザイン、状態見本、共通表示部品。
- mae さん：参加者向けモバイルの処理、カメラ、送信、API接続、復帰。
- さが さん：DB/R2、ゲームルール、締切、加点・順位、認可、永続化。
- Ahwenu：HTTP契約とルート、外部API/AI処理、MCPサーバー・Sites接続。
- Plugin Extensionsの画面開発：未定（Ahwenu）。暫定候補を正式担当として扱わない。

API層はゲームサービスを呼び、加点・締切判定を重複実装しない。具体的な作業・受け渡しは07を正本とする。

## 代替案と理由

バックエンド/APIを一括担当、モバイル/ホストをフロントエンド担当が兼任する初期案は、ユーザーの担当指定に合わせて分割した。

## 影響とトレードオフ

共有DTOとゲームサービスの関数契約を先に揃える必要がある。拡張画面担当の正式決定は未完了であり、mae さんへ暗黙に割り当てない。

## 検証・見直し条件

最初のAPI結合で責務の抜け・重複を確認する。担当変更や拡張画面担当の確定は後継ADRと07に反映する。
