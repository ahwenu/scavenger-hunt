# ADR-0010: AhwenuのAI APIをSitesから分離し、拡張からサーバー経由で利用する

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：Ahwenu、Sites側の関係担当。拡張画面は未定（Ahwenu）
- 決定の根拠：Sitesは他担当、AhwenuはAPI処理を担当し、利用者が指定した既存キーを使うというユーザー指示。採用対象は責務・秘密の境界であり、実AI成功は検証結果で別途記録する
- 置き換えるADR：なし。ADR-0002のAPI担当境界、ADR-0008の独立拡張を具体化
- 後継ADR：なし

## 背景

API担当がSitesの画面・ゲーム実装や配備設定まで同時に変更すると、他担当と競合する。拡張へ外部AIをつなぐ際にも、OpenAIキーをブラウザや配布プラグインへ渡さずサーバー側で扱う必要がある。

## 決定

- `api/` を独立したHTTP AIサービスにし、お題生成・写真判定・認証付き参考写真取得を提供する。Sitesの `apps/cloud/` や配備設定は今回の作業対象にしない。
- 標準の文章のお題生成はResponses APIのStructured Outputs（strict JSON Schema、`store: false`、20秒、自動再試行なし）を使う。`AI_REFERENCE_PHOTOS=true` を明示したときだけAgents APIとWikimediaを使う。写真判定はDecisions APIで行う。失敗を固定プリセットで自動補完しない。
- APIは外部AI接続と結果の正規化を持ち、部屋・参加者・締切・採点・ランキング・ゲームDBの正本を持たない。Sitesは後続作業でサーバー間HTTP接続する。
- pluginのMCPサーバーから `ai_status` / `ai_generate_challenge` でAPIを呼ぶ。実AI確認の表示をゲームデモから分離し、生成結果をサンプル順位へ混ぜない。
- OpenAIキーはAPIサーバーだけが利用する。利用者指定の既存ファイルを `OPENAI_KEY_FILE` で参照し、キーや実際のパスを文書・Git・UIへ複製しない。サービス通信用トークンは別ファイルで共有する。
- `api/` と `plugin/` は自己完結したパッケージを保つ。各 `.env.local` は起動時に任意で読み込み、Git・配布物へ含めない。
- 現段階はローカルAPIとMCP接続の実装・検証を対象とする。公開配備、Sitesのゲーム結合、実Plugin Extensions登録は別途実証する。

## 代替案と理由

Sitesの既存コードへ直接外部AI処理を追加する案は他担当の作業領域へ変更が及ぶ。ブラウザやpluginへOpenAIキーを配る案は秘密の境界を増やす。独立HTTPサービスとMCPのアダプターで受け渡し、Sitesには契約と接続設定を提供する。

## 影響とトレードオフ

ローカル開発ではAPIとpluginを別々に起動する。API内のお題・参考写真は一時的なメモリ保持であり、再起動後の復元やゲームラウンドへの適用はSites側との接続設計が必要になる。公開配備時の認可・期限・到達性を本決定だけで実証済みと扱わない。

## 検証・見直し条件

最新の確認（2026-10-18）：ユーザーのWork内実Plugin Extensionsでの「API接続確認」→「AI生成」操作と提供画像2枚により、画面表示・API利用可能/接続済み・お題「文房具のペンを探そう」の生成表示を1例確認。条件「文房具のペンが写っている」「ペンに細長い形が見える」、120秒も表示された。ユーザー操作と画像を根拠とし、Codexによる直接UI操作とは区別する。写真判定UI・Sitesのゲーム進行・参加者・得点・順位の結合は未検証。

独立APIの認証・入力・写真・秘密値保護・重複要求・失敗応答、MCPクライアントの認証・タイムアウト・応答検証を確認する。参考写真付きAgentsの初回試験は原因未特定の502。その後の参考写真なし・旧Agents方式の文章生成で `text_agent_cleanup_failed` を確認したため、セッション管理を要しないResponsesを標準生成に採用した。参考写真モードの成功は未確認とする。

2026-10-18、変更後の構成で次を確認した。

- APIの18件・pluginの15件のテストが成功。
- pluginの単独配布物の可搬性検証で10 MCPツールとUIリソースを確認。
- ブラウザプレビュー→stdio MCP→独立API→Responses APIで「紙コップを探そう」の生成・表示が成功。
- 同じお題のIDと、取り込み済みバナナ画像を正規化したJPEGを判定APIへ送り、HTTP 200 / `fail` / `CRITERIA_NOT_MET` / `Decisions API` を確認。

実接続の1例として記録し、判定精度の評価は継続する。写真判定UI、参考写真付きAgentsモード、公開配備、SitesのゲームAPI接続、複数スマホのゲーム進行・得点・順位は未検証。

追加指示によるローカル登録で、公式CLIの一覧から `karimono-host@karimono-local` のインストール・有効化・version 0.1.0を確認した。キャッシュの `.env.local` にはAPI URLとサービス用トークンファイル参照だけを0600で設定し、OpenAIキーは複製していない。拡張内のUI表示・実AI生成は、後続のユーザー操作と画像で1例確認した。ブラウザプレビューの実AI成功とは分けて記録する。

登録済みキャッシュのサーバーへのstdio接続では、`ai_status` が `available: true` を返した。チャットに公開された `host_open` の呼出しも成功した。実拡張画面からのAI生成は、後続のユーザー操作と画像で1例確認した。
