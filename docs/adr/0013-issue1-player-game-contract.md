# ADR-0013: Issue #1の100人・10競技・初合格500点のゲーム契約

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：さが（ゲーム・保存）、Ahwenu（HTTP/API）、mae（参加者画面）
- 決定の根拠：ユーザーの「Issue #1のバックエンド側の改修を進めて。コミットやプッシュはまだしない」という指示
- 置き換えるADR：なし。ADR-0005のProposedの人数・問題数・得点案に対し、本Issueの採用範囲を確定する
- 後継ADR：なし

## 背景

[Issue #1](https://github.com/ahwenu/scavenger-hunt/issues/1)は、同一QRから約100人が全員プレイヤーとして参加し、参加者画面がサーバー確定の得点・ステージ・ヒントを使うことを要求している。既存Sites実装には受付と判定キューがあるが、500点、全10ステージ、ゲーム終了、共有ヒントの契約がない。

## 決定

- 既存の `apps/cloud/` と `/api/rooms/:id` を拡張する。参加者はBearer、ホストは既存の部屋限定HttpOnly Cookieを維持する。参加上限は100人、成功201、満員409。観覧モードを追加しない。
- 最大10競技、同時に1競技。既存の初回30秒自動開始とホストの強制開始を保持し、2競技目以降はホストの `host/start` のみ。`host/end` は現在競技の受付を閉じる既存操作で、途中の全ゲーム終了には読み替えない。
- 各プレイヤー・競技の最初の期限内受付の合格だけ500点。既存 `submission_active_player` 部分一意インデックスが合格済みの追加受付を防ぎ、`recordPass` が提出と通知を原子的に確定する。得点は永続した合格提出から集計し、点数用の重複した正本を作らない。集計側でもプレイヤー・競技を重複排除する。
- 順位は得点降順、合格受付までの累計時間昇順、参加時刻昇順、IDのコードポイント順。順位番号は1始まりの連番。同点同順位の旧案は採用しない。
- 状態には `game`、全10件の `stages`、`ranks[].score/rank`、`mine[].awardedPoints` を追加する。既存フィールドを保持し、未来のお題を返さない。内部uploadingは参加者へqueuedとして返す。
- 開始前は `round=null`。競技間・終了後は直前の `round.status=closed` を保持する。10競技目の受付終了かつ受付済み判定が全件確定した時点でfinished。11競技目は作成不可。受付後の判定待ちは加点確定前のためfinishedにしない。
- 未処理uploading/queuedは受付から120秒、processingは既存65秒リースを期限とする。リース失効した合格応答は反映しない。期限前に受付済みなら、競技締切後のリース内判定は確定可能。
- ヒントは `rounds.hint` に保存する。参加者のGETは現在参加可能な競技だけ。未用意は `{text:null,available:false}`、未来・終了競技は409。ホストの `POST host/hint` で1〜500文字を登録し、nullで削除する。生成結果にhintが含まれる場合は出題時に保存するが、既存AIを変更したり閲覧ごとに生成したりしない。
- 既存の写真受付・画像形式・1MiB制限・1競技8提出・同時1提出・D1/R2を維持する。Supabase移行、独立AI APIのお題登録、Plugin接続、UI変更は含めない。

## 代替案と理由

画面で `wins*500` やステージ解放を計算する案はIssueの要望と異なる。既存APIを `/api/v1` の初期提案へ全面移行する案は担当間の接続範囲を広げるため行わない。ヒント閲覧時のAI生成は100人の重複実行を招くため行わない。

## 影響と受け渡し

SQLとDrizzleメタデータは `0003_issue1_round_hint` として追加生成し、過去のマイグレーションを変更しない。配備前にこの変更を適用する。ルートとレスポンスの最小変更は今回のバックエンド対応に含め、[受け渡し](../12-issue1-backend-handoff.md)をAhwenu・mae向けの参照とする。Pluginの独立デモDTOとは別契約であり、Pluginへゲーム結合を行ったとは扱わない。
