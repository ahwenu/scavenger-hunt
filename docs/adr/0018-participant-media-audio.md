# ADR-0018: TypeScript参加者画面の音を初期オンとし、メディア再生経路へまとめる

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：mae さん（参加者画面）、Akibako さん（UI）
- 決定の根拠：ユーザーの「リポジトリの効果音を現在の画面へ適用」「音はデフォルトON」「スマホのマナーモードでも再生したい」という追加指示。Acceptedは適用方針であり、全端末での再生確認ではない
- 置き換えるADR：なし。ADR-0014の素材・出典・ゲームイベント方針を継続し、TypeScript参加者画面の再生経路を追加する
- 後継ADR：なし

## 背景

ADR-0014のOtoLogic 11種類は従来の `apps/web/` とPluginに実装済みだが、TypeScript参加者画面は別の撮影音・成功音だけを使っていた。現在の画面へ同じゲーム演出を接続することと、ユーザー指定BGM・キャラクターの声を一緒に制御する必要がある。

iOSでの消音スイッチとWeb Audio/メディア再生の違いは、[WebKitの報告237322](https://bugs.webkit.org/show_bug.cgi?id=237322)に記録されている。同資料にはiOS 17以降の `navigator.audioSession.type = 'playback'` も案内されている。対応するブラウザでこの設定を使い、HTMLAudioによるメディア再生へまとめる方針とする。これを実機動作の保証として扱わない。

## 決定

- TypeScript参加者画面は音を初期オンにする。利用者が保存したオフ設定は尊重し、画面の音ボタンから切り替えられるようにする。
- 再生の開始は最初の参加・タップ操作を契機とする。音の初期オンと、ブラウザの自動再生許可を同じ状態として扱わない。自動再生制限については[AppleのSafariメディア資料](https://developer.apple.com/documentation/webkit/delivering-video-content-for-safari)を参照する。
- 効果音、既存の声、ループBGMはHTMLAudioのメディア再生経路を使う。対応環境では音声セッションを `playback` に設定する。端末のメディア音量やブラウザの再生拒否は画面側から強制解除しない。
- ADR-0014のOtoLogic 11種類、出典表示、同一オリジン配信、初回・同期の重複抑制を引き継ぐ。声は短い効果音と競合しない間隔で再生する。
- オフ、タブ非表示、画面破棄時には効果音・声・BGMを止め、待機中の過去の演出を破棄する。復帰時はBGMを再開し、見ていなかった間の開始・結果・声を再演しない。
- 変更範囲はTypeScript参加者画面とその配信素材。従来の `apps/web/` とPluginのWeb Audio実装、およびAPI・採点・認可は維持する。

## 代替案と理由

従来と同じWeb Audio実装をそのまま取り込む案は、再利用範囲が広い一方で、マナーモード中にも鳴らしたいという追加指示への対応を別に要する。今回は既存BGM・声と同じメディア再生経路を使い、ゲームの差分検知と素材対応を再利用する。

## 影響とトレードオフ

初回の操作以前は、音の設定がオンでも再生できない場合がある。端末ごとのメディア音量・省電力設定・ブラウザの許可状態に依存する。再生できない場合も、視覚的な操作・得点表示を継続する。

Web AudioとHTMLAudioの再生部分は分かれるため、素材の一致とゲームイベントの重複抑制をテストする。バックエンドやPluginの配布境界へ音声生成の依存を追加しない。

## 検証・見直し条件

実装後の音31件の自動確認、TypeScript型検査・Cloudビルド、Chromeでの初期オン・保存済みオフ保持・再オン・クレジット表示を確認した。詳細は[効果音仕様](../15-sound-effects.md)へ記録する。iPhone/Android実機のマナーモードでの試聴、100端末の会場利用、今回変更後の公開再配備は未実施。

猫の声は指定の「さっちゃん」へ統一し、9本の短語にする追加指示を受領した。ブラウザで指定Voice IDを照合し、Eleven v4で生成した9本を配信用フォルダへ配置した。採用した台詞・ファイル・長さと実機未確認の範囲は[音声の引き渡し](../design/participant-assets-and-audio.md)で区別する。別の声は指定声の代用として採用していない。
