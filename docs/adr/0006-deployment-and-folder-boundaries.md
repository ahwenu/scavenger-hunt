# ADR-0006: デプロイを優先し担当別フォルダとビルド単位を分ける案

- 状態：Proposed
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：全員。拡張画面担当は未定（Ahwenu）
- 決定の根拠：デプロイの容易さを最優先に競合を減らすというユーザー指示。具体的な配置・ビルド独立性は未検証の提案
- 置き換えるADR：なし
- 後継ADR：なし

## 背景

デザイン、モバイル処理、ゲーム処理、API、拡張UIが同じリポジトリで進行する。配置だけでなく、依存・配備設定・生成物の同時更新も競合の原因になる。

## 提案

Sitesはリポジトリ直下、プラグインはplugin/をルートに独立してビルドする。最初はワークスペース管理や共通パッケージの事前ビルドを必須にしない。UI部品、モバイル処理、ゲーム/保存、HTTP/外部API、拡張UIを担当別の機能フォルダに分ける。

共有DTOは依存なしのcontractsに置き、plugin配布物にはビルド時に取り込む。DB履歴はさが さん、依存/配備設定はAhwenu、デザイントークンはAkibako さんが取りまとめる初期案とする。具体的なパスは09を正本とする。

## 代替案と理由

apps/siteとapps/pluginを持つワークスペース構成は拡張性があるが、MVPではSites配備ルートや共通ビルドの設定が増える。両UI・MCP・バックエンドを一つの依存/出力先にまとめる案は、Node依存の混入とlock更新の衝突が増えるため避ける案とする。

## 影響とトレードオフ

ビルド単位ごとに依存を持つ分、設定の一部は重複する。契約と共有設定の調整は残るため、コンフリクトが一切起きないとは保証しない。フォルダ担当と変更の統合順序を併用する。

## 検証・見直し条件

Sitesだけのクリーンビルド、pluginだけのビルドと単独配布、contractsの取り込み、Sites配備からのplugin除外、マイグレーション適用を確認する。スターターが別配置を要求する場合は配備しやすさを優先して提案を修正する。
