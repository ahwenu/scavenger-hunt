# ADR-0019: 新しい参加者画面をサイトのルート入口にする

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：mae さん（参加者画面）、Akibako さん（UI）、Ahwenu（Sites配信）
- 決定の根拠：ユーザーの「新しい画面のトップをルート `/` で開く」という確定指示。リポジトリの配信設定へ実装し、再デプロイ時に反映する
- 置き換えるADR：[0015](0015-participant-typescript-ui.md)。同ADRのTypeScript参加者画面・既存API境界・比較画面の判断は継承し、ルート入口だけを変更する
- 後継ADR：なし

## 背景

ADR-0015では、参加URLだけをReactへ通し、サイトのルートは従来の部屋作成画面を維持した。追加指示により、サイトURLを開いたときにも猫とロボットの新しいスタート画面を表示する。

## 決定

| URL | 役割 |
| --- | --- |
| `/` | 新しい参加者スタート画面。ゲームスタートから参加リンクまたは部屋IDを入力する |
| `/rooms/:id/join` | 既存QRの参加先。部屋の名前登録・撮影・結果・順位表示を継続する |
| `/design-preview` | 8画面の原画と実装の比較。実参加や実AI判定は行わない |
| `/host` | 従来の部屋作成ページを互換用に配置する |
| `/rooms/:id/host` | 既存のブラウザ用ホスト画面を維持する |

ルート画面は部屋を自動作成しない。部屋作成の正式な入口はPlugin Extensionsとし、ルートからは入力された同一オリジンの参加URLへ移動する。APIの採点・締切・順位・認可は変更しない。

現在のSitesソースは `apps/cloud/` のままとし、Workerのルート分岐とReactのページで入口を切り替える。リポジトリの変更と公開サイトへの再配備は別の完了条件として記録する。

## 継承する判断

提供デザインに沿ったTypeScript/Reactの参加者画面、画像素材の静的配信、既存 `/api/rooms/:id` との境界、サーバー確定得点の表示、デモ比較画面の分離はADR-0015から継承する。Supabase・人数/順位の追加契約はADR-0016、音の再生経路はADR-0018を参照する。

## 代替案と理由

部屋ごとのURLだけに新画面を置く案は、サイトURLを開いて新しいトップを見たいという指示に沿わない。ルートから固定のデモ部屋へ入る案は、実参加と見本を混同するため採用しない。参加リンクか部屋IDを明示して、既存の参加先へ移動する。

## 影響とトレードオフ

従来ルートで部屋を作成していた検証手順は `/host` へ変わる。発行済みQRの `/rooms/:id/join` と部屋ごとのホストURLは継続する。公開サイトの入口変更はソースのcommitだけでは反映されず、Sitesの再配備が必要。

## 検証・見直し条件

TypeScript型検査・Cloudビルド、参加先の入力検証4件が成功。ビルド版のローカル配信で `/` の新トップと `/host` の旧部屋作成HTMLを確認した。Chromeでは新トップから入力欄を開き、外部URLを拒否して同じルートへ留まることを確認した。今回、公開再配備・実機確認・実部屋への新規参加は行っていない。既存の `/rooms/:id/host` はコードで配信分岐の維持を確認し、今回の新しい結合試験とは区別する。検証結果は[作業レポート](../ai-reports/2026-10-18-参加者効果音と音声の接続.html)に記録する。
