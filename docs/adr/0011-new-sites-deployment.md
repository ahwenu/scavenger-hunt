# ADR-0011: 新Sitesへ全ソースを保持し、Cloud実行とPlugin Extensionsの接続を分ける

- 状態：Accepted
- 作成日：2026-10-18
- 最終更新：2026-10-18
- 関係担当：Ahwenu、Sitesの関係担当。拡張画面は未定（Ahwenu）
- 決定の根拠：最新コードを新Sitesへ配置・配備し、Plugin Extensionsと連携するというユーザー指示。Acceptedはこの作業方針であり、配備・実ゲーム連携の成功を意味しない
- 置き換えるADR：なし。既存ローカル構成を残して新Sitesの実行・接続を追加
- 後継ADR：なし

## 背景

リポジトリにはCloud、ローカルデモ、独立Node API、stdio MCP拡張があり、実行環境が異なる。全ソースを新Sitesに持たせながら、WorkersへNode専用サービスまで混入させず、ホストの部屋権限を維持して接続する必要がある。初期privateの配備後、追加指示によりログイン不要のpublicへ変更した。

## 決定

- 最新main `a67a393695e291c1695598ca49a8f135d567a94e` を取得元とし、新Sites作業ルートへCloud実行アプリを配置する。テンプレートと公式のビルド/配備構成を維持する。
- 全591追跡ファイルは `repository/` へ保存用スナップショットとして置き、型チェック/ビルド対象から除外する。旧hostingのproject_id、秘密設定、実行時状態、依存・生成物を含めない。
- Express/Sharpの独立APIとstdio MCPはソースとして保持し、Workers上では起動しない。CloudがDB・画像保存とゲーム処理を実行する。
- Cloudの標準お題生成はResponses単発、参考写真は `AI_REFERENCE_PHOTOS=true` の明示設定時だけAgents、写真判定はDecisionsとする。利用者承認済みのキーはSitesの秘密設定 `OPENAI_API_KEY` で使う。
- 新Sitesは追加指示に従いpublicとし、pluginは明示的なsitesモードで接続する。今回の接続にはサービスアクセス資格情報を使わない。アプリのホストCookieはMCPサーバー内部で保管する。private用ヘッダーの任意対応は今回のpublic設定と分ける。
- 既存Cloudの勝利数順位とラウンド終了へUI表現を合わせ、全ゲーム終了や10点加点を実装済みと扱わない。
- 今回の新Sites配備・連携に必要な範囲で、Workers向けAIアダプターと既定AIモード・見本なし表示の差分を元の `apps/cloud/`・`apps/web/` へ戻し、元リポジトリの最新作業ツリーから保存用スナップショットを同期する。以前のAPI単独作業の非変更境界と、この追加作業の範囲を分ける。

## 代替案と理由

全コードを同じWorkers出力へ取り込む案は、Nodeのサーバー・画像処理・stdio起動が実行環境と合わない。Cloudだけを残す案は全ソース保持の指示を満たさない。実行ルートと保存用スナップショットを分け、移行後も元の版と実行環境を追えるようにする。

## 影響と制約

配備先と元リポジトリの差分管理が必要になる。スナップショットは実行コードの二重編集先とせず、取得元のコミットを記録して更新する。

publicへの変更後も、サーバーのOpenAIキーとアプリの部屋権限を維持する。Cookieや秘密値を参加URLやUIへ出さない。現時点のCookie保管はプロセス内mapであり、MCP再起動後の部屋復帰は未解決。一般参加者のアクセスと実機のゲーム結合も検証が必要。
