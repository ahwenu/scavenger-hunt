# 要件・MVPと完成版

チーム名は **ONE LEASE**、アプリ名は **カリモノ**、キャッチコピーは **「借り物王に俺はなる！」** とする。現在の名称方針は[ADR-0007](adr/0007-product-identity.md)に記録する。

## 目的と利用者

イベント会場で、身近な物を探す・撮る・判定を待つ・順位を見る体験を提供する。ホストはCodexのPlugin Extensions内の管理画面、参加者はスマホのブラウザで操作する。参加者はアプリのインストールや屋外移動が不要。ホストはプラグインの導入が必要になる。

以下は開発開始のための推奨初期仕様であり、ユーザーから指定されていない数値はチームで変更できる。

## 作る範囲

| 項目 | MVP：会場で1ゲーム成立させる | 完成版：継続的にイベント運用できる |
| --- | --- | --- |
| 配信 | 参加者はSitesのモバイルWeb、ホストはPlugin Extensions | 両画面の公開運用、ホスト画面の大画面表示 |
| 部屋 | 作成、6桁コード参加、待機、開始、終了 | 複数部屋の運用、設定保存、再開催 |
| チーム | 1チーム1代表端末、表示名で参加 | 複数メンバー・複数端末、招待、代表交代 |
| お題 | 共通3問、各120秒、開始前にAIで一括生成 | テーマ・難易度・会場条件・問題数の設定、編集・再生成 |
| 撮影 | 背面カメラ、プレビュー、撮り直し、送信 | 端末別改善、複数候補の選択、使いやすさの継続改善 |
| AI判定 | 実写真を条件判定、合格・不合格・不明 | 評価データ拡充、閾値改善、ホストの異議対応 |
| 得点 | 合格1回につき10点、ラウンドごとに最大1加点 | 採点ルール設定、難易度別得点、公平性の分析 |
| 同期 | 2秒間隔のポーリング、再読込で復帰 | 必要性を計測してSSE等を検討、復帰・負荷対策を強化 |
| 結果 | ラウンド順位、最終順位、同点は同順位 | 履歴、共有、主催者向け集計・出力 |
| 参考写真 | 不要。文章の条件だけで判定 | Wikimedia Commons検索、出典表示、参考画像との条件比較 |
| 演出 | 画面内の合否表示と順位更新 | 効果音・任意の振動・演出。OS通知は必要性と対応状況を別途検討 |
| 運用 | 通信エラー、判定失敗、終了後画像削除 | 再審査、監査履歴、稼働監視、負荷試験、保持期間設定 |

MVP・完成版とも、参加者はスマホのブラウザで使う前提とする。ホスト画面はPlugin Extensions内に実装する。決済、GPS、AR、顔認識、SNS連携は現時点の完成範囲に含めない。

## MVPの固定ルール

- 全チームに同じ問題と同じ締切を配る。チームごとの先行進行はしない。
- 最大10チーム、同時1部屋を最初の検証対象とする。これは性能保証値ではない。
- ロビー中のみ参加可能。開始時に参加チームと3問を確定する。
- ホストが開始・次の問題へ進む・最終終了を操作する。参加者の「次へ」は結果画面への遷移だけであり、全体の問題を進めない。
- 各問120秒。サーバーが受理した時刻が締切未満の提出だけを採点する。撮影開始時刻や端末時計は採用しない。
- 1チームにつき同時判定は1件。1問で最大5回提出できる。通信上の同一リクエスト再送は回数に含めない。
- 不合格・不明は締切前なら撮り直せる。合格後は追加提出不可。速さによる加点や減点は行わない。
- 締切前に受理した判定の確定猶予を最大30秒取る。締切後は新規提出不可、猶予終了まで次問へ進めない。未確定分は失敗・0点で確定する。
- 同点は同順位とし、表示順だけチーム参加順で固定する。順位は1位・1位・3位方式。
- AI停止時もホストが終了できる。生成失敗には用意済みのお題を使える。写真判定失敗を自動合格にはしない。

## MVP完了条件

1. ホストがPlugin Extensionsで部屋を作成し、参加者一覧・ランキング・進行操作を同じ拡張内で使える。3チームがSitesへ各スマホから参加できる。
2. AI生成した3問を共有し、スマホから実際に撮った写真をAIに渡して合否を表示できる。
3. 合格で10点が入り、他端末でも通常3秒以内を目標に順位が更新される。
4. 3問終了後に最終順位が確定し、再読込しても得点が維持される。
5. 二重送信、締切直前の送信、カメラ拒否、通信切断、AIタイムアウトで進行不能や二重加点が起きない。
6. iPhone SafariとAndroid Chromeの実機で一連の流れを確認する。

目標値の判定時間・同時利用数は実測で確定する。モック判定だけではMVP完了としない。
