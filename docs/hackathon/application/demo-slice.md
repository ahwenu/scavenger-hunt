# 実演する1周と受け入れ条件

更新: 2026-10-18。これは当日の結合順序の**提案**です。ゲームルールの正本は[01](../../01-product-scope.md)と決定後のADR、画面の正本は[03](../../03-ui-frontend.md)。[未決事項](../domain/goal-and-decisions.md)の決定前に、1問案を採用済みの仕様として扱いません。

## 人が見る1周

1. ホストが部屋を作り、参加URL/QRを見せる。参加者はスマホの公開Sitesで名前を入力し、ロビーに入る。
2. ホストが今日決めたルールでお題を公開する。参加者全員に同じお題と残り時間が見える。
3. 参加者が会場の物を撮影してプレビューを確認し、写真を送る。送信中と判定中は二重操作を防ぐ。
4. 実AIの合否・不明または処理失敗を区別して表示する。得点・順位はSitesのゲーム側が確定した値だけを使う。
5. ホストで参加者の状態と順位を見る。次問・終了の操作は、[進行条件](../domain/goal-and-decisions.md)を確定してから合わせる。

## 状態の受け渡し

| 状態 | 参加者に見えること | ホストに見えること | 正本・依存 |
| --- | --- | --- | --- |
| ロビー | 参加済み、開始待ち | 参加者一覧、開始条件 | Sitesの部屋・参加者データ |
| お題公開 | 同じお題、締切、撮影ボタン | お題と進行状態 | Sitesのラウンド。AI APIはお題候補を返すだけ |
| 撮影・送信 | プレビュー、撮り直し、送信中 | 提出状況 | スマホのカメラ、Sitesの受付API |
| 判定中 | 合否未確定の表示 | 判定中件数 | Sitesの提出状態と独立AI APIの判定結果 |
| 合否確定 | 合否・不明・失敗を区別、再挑戦可否 | 確定結果、順位 | Sitesが締切・加点・順位を確定 |
| 終了 | 最終結果 | 終了操作と結果 | Sitesの永続記録 |

## 結合の順番

1. Ahwenuとさがさんが、部屋・お題・提出・順位の**入出力例を各1件**合わせる。独立AI APIの `challengeId` をSitesのラウンドへどう結び、20分の一時保持・再起動をどう扱うか決める。
2. Akibakoさんのデザイン画像を受け取り、maeが参加・撮影・結果の状態へ割り当てる。画像にない失敗・読込・判定中の表示は確認してから組み込む。
3. 固定お題と仮判定で、Pluginホスト→Sites→スマホ2台の1問を通す。仮判定の結果を「実AI」と説明しない。
4. Sitesのサーバーから独立AI APIへ実写真を渡し、合否をゲーム記録に確定させる。失敗・再送・締切を短く試す。
5. 公開URLで別端末から再度1周を通し、README・発表で見せる実際の動作を記録する。

3が未成立なら、どの経路が未接続かをチームへ示し、公開済みプロトタイプで実演できる範囲と差を確認します。ゴールを黙って「結合完了」へ変更しません。

## 出来たかどうかの記録

| 確認 | 証拠として残すもの |
| --- | --- |
| 公開 | 公開URL、GitHubコミット、別端末で開いた時刻 |
| 参加・撮影 | 2台の端末とブラウザ、QR/リンクから合否までの操作記録 |
| 実AI | 生成・判定の実行経路、結果の種類、デモ判定との区別。キーや写真本体は載せない |
| ゲーム整合 | 再送で二重加点しない、締切後に受理しない、結果がホストへ反映する |
| 使いやすさ | 初見の人が迷った箇所と、直した画面・文言 |

現在の[既存デモ](../infrastructure/current-state.md)の成功記録は、この結合確認の代わりにしません。
