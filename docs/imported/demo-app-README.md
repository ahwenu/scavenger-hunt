# AI借り物競争

スマホで部屋に参加し、共通のお題を写真でクリアするゲーム。`apps/web`（共通画面）、`apps/server`（ローカルNode + SQLite）、`apps/cloud`（Sites / Cloudflare + D1 + R2）のモノレポです。

## 使い方

トップ画面で名前を入れて「部屋を作成」。作成したブラウザがホストになり、部屋固有のQRと共有リンクを表示します。参加者はそこからニックネームを登録でき、参加コードの入力はいりません。実AIを使う場合は、参加者の登録前にホストのモードを切り替えます。デモは固定のお題と選択した合否を使い、写真の内容は評価しません。

最初の参加登録が成功すると、その部屋のサーバー時刻で30秒後に初回ラウンドを開始します。部屋を作っただけでは時計は動きません。後からの参加や再接続でも期限をリセットしません。待機中に共通のお題を準備し、初回の生成入力は準備開始時に固定します。ホストは「いますぐスタート」または「+10秒追加」を使えます。期限になっても準備が終わっていなければ準備中のまま待ち、失敗時はエラーを表示します。ホスト画面を開き続ける必要はありません。

初回終了後は、ホストが次のお題を開始します。「先にお題を準備」で事前生成も可能です。初回後の準備は参加者・モードの変更や5分経過で無効化し、開始時に生成入力を確認します。

秋の運動会をイメージしたホスト画面は、QR・お題・操作・上位順位を一画面にまとめています。全順位や詳しい設定は展開して確認できます。1280×720、1366×768、1920×1080、1024×768でページのはみ出しがないことを実ブラウザで確認しました。

参加画面はカメラを中心に表示します。許可ボタンで映像を開き、シャッター1回で画面に見えている範囲を撮影・送信します。許可しない場合や非対応端末は端末の写真選択を使えます。写真選択も必ずJPEGへ再圧縮してから自動送信し、別の送信ボタンは不要です。応答が不明な場合は自動再送せず、明示再試行だけ同じ受付キーを使います。画面を離れるとカメラを止めます。

開始後は全員が同じお題を見て撮影します。実AIモードは参考写真を併せて表示し、同じ種類・大まかな色や形の実物を探します。端末で写真を最大960px・1MB以下に縮小し、サーバーがHTTP202で受付、最大8並列で判定します。順位はAIの完了順ではなく、サーバーの写真受付時刻順です。途中参加者は次のラウンドから挑戦できます。

- 参加リンクはOS共有、非対応時はクリップボード、さらに非対応時は選択可能なURL欄から共有できます。
- QRはPNGファイル共有・ダウンロード・保存に対応します。
- ホスト権限は部屋ごとのHttpOnly Cookieで保持します。Cookie削除や別ブラウザへの移動では引き継がれません。
- 自分の合格がサーバーで確定したときだけ成功表示と短いジングルを出します。音は参加・送信などの操作後に有効化でき、画面のボタンで消音できます。音を使えないブラウザでも視覚表示は続きます。
- 他の参加者の成功は短い通知で表示します。連続成功はまとめ、再送・再読み込みで過去の成功を再演しません。動きを減らす端末設定にも対応します。

## 公開版

[公開サイト](https://ai-karimono-race.ahwenu.chatgpt.site/) · [写真付きの検証記録](https://ai-karimono-race.ahwenu.chatgpt.site/verification.html)

OpenAI・ChatGPT・Sitesへのログインは不要です。ニックネームだけで参加し、ホスト操作には作成したブラウザのゲーム用Cookie、写真投稿と自分の結果取得には部屋用参加者トークンを使います。プラットフォームCookie、既存のブラウザセッション、Sites bypassを使わない新規Node HTTPクライアントで公開動作を検証しています。

公開スモークでは、実際の最初の登録から期限まで30,000ms、ホスト開始操作なしで期限後約0.41秒の自動開始を確認しました。部屋間分離、延長、即時開始、QR、写真受付から合格通知・順位反映も成功しています。記録は `docs/public-smoke.json`。

最新の公開70接続・70枚約17.05MBのデモ負荷は全件受付・合格・永続合格イベントの観測に成功し、エラー0でした。受付p95 **3.74秒**、合格結果・イベント観測p95 **8.21秒**、全件観測 **8.68秒**。同期は1秒±30%のジッター付きです。`docs/load-test-public.json` を参照してください。登録中はホストが待機時間を延長し、70人が揃ってから即時開始しました。延長なしの30秒動作は別の公開スモークで検証しています。

この負荷試験は1台から70独立HTTPクライアントを動かしたデモ判定です。実機スマホ70台、会場Wi-Fi、70件の有料AI同時判定の性能保証ではありません。

## ローカル起動

Node 22.13以上。

```sh
npm install
npm run dev
```

[ローカルトップ](http://localhost:4317/)から操作できます。QRは検出したLAN IPv4を使い、同じWi-Fiの端末から参加できます。`PUBLIC_URL`でQR先、`PORT`でポート、`DATA_DIR`でSQLite保存先を指定できます。会場Wi-Fiの端末間通信制限がある場合は公開版を利用できます。

旧プロトタイプのデータは削除せず `legacy` 部屋へ移行します。以前のホストCookieはその部屋だけに通用します。旧URL `/host` `/join` はトップへ移動します。

## 実AI・参考写真・秘密

公式OpenAI Agents APIで、部屋内の共通のお題・判定基準・参考写真を準備します。実装した検索ツールで再利用可能なWikimedia Commons写真を探し、取得した実画像バイトと出典・作者・ライセンスを保存します。開始前はお題も参考写真も公開せず、開始後は部屋に紐づく参考画像URLを配信します。実行された検索・取得ツールの記録は、開始後にホストだけが確認できます。デモでは検索や有料AI呼び出しを行いません。

生成入力には部屋内で実測した参加人数、未回答人数、自己申告情報、回答率、正解率、過去のお題を使います。初回だけは、後からの参加で生成を繰り返さないよう準備開始時の入力を固定します。お題を人数分生成することはありません。

Decisions API（`gpt-6-luna`）には参考写真と提出写真の両方を送り、提出側に実物が写ること、生成した各条件、大まかな種類・色・形の類似、参考写真の複製ではないことをpredicateで評価します。2条件のお題なら合計5つのpredicateで、すべての確率が0.8以上の場合だけ合格です。背景・ブランド・撮影角度・画素の一致は要求しません。拒否や通信失敗を合格に置き換えません。

参考写真そのものの投稿はハッシュで拒否し、圧縮などの複製も判定条件で確認します。これらは、その場で新しく本人が撮影したことや、あらゆる画像加工を検知できることの証明ではありません。公開実AI試験では、参考写真そのものを409で拒否、圧縮コピーを不合格、別のバナナ写真を合格として永続イベント74・1位を確認しました。参考画像の70同時取得も全件成功（1119ms）。これは既存の再利用可能な写真による試験です。

公開実AI経路の最新の成功・失敗、各条件の返値、出典とツール記録は `docs/public-reference-smoke.json` に保存します。閲覧用レポートの新しい参考写真経路は、この記録が成功した場合だけ掲載します。

ローカルは既存 `../1018_hackason/.env.local` を実行時に読み、値を表示しません。`OPENAI_KEY_FILE`で既存ファイルを変更できます。キーはソースやフロントへ埋め込みません。公開版はSitesの `OPENAI_API_KEY` secretを使います。

## 集中投稿・合格イベント・順位

- 写真受付とAI処理を分離し、202後は二重送信を止めて待機・判定中・失敗を表示します。
- 最大8並列、部屋内100件・全体200件までのキューです。飽和時は再試行を案内します。
- 同じリクエストIDの再送は同じ受付を返します。1ラウンド1合格とし、判定中の追加受付や同じ写真の重複を防ぎます。
- 合格の確定と `pass_events` の記録を同じDBトランザクションで保存します。判定前・不合格・保存失敗から成功通知を作りません。イベントIDは再送や再取得でも変わりません。
- 部屋の公開履歴は最新40件です。自分の合格は参加者専用状態の `passEventId` でも取得でき、公開履歴から流れた場合も確認できます。
- 先行写真の判定が残る間は順位を暫定として扱い、現在の受付時刻順で再計算します。ローカル統合テストで、後から確定した先行写真によって既存イベントの順位が1位から2位へ更新されることを確認しています。
- ローカルはsharpの非同期処理を8件までに抑え、SSE通知を40ms単位でまとめます。公開版はR2一時保管とD1条件付きUPDATEでWorker全体の判定リースを制御します。
- 公開画面は実行中・判定待ちに0.8〜1.4秒、通常待機に1.5〜2.5秒、バックグラウンドに8〜12秒のジッター付き同期を行い、復帰時にも同期します。
- 公開版は判定後にR2の提出画像を削除します。ローカルは提出画像をメモリ内だけで保持します。参考写真はラウンドの共有証拠として別に保存します。
- 総合順位は合格数が多い順、合格までの累計受付時間が短い順。同値は登録時刻・ID、ラウンド内の同一ミリ秒はDB受付順で決めます。

カメラの模擬APIテストと実ブラウザ確認、実機未検証の範囲は [カメラ・画面検証記録](docs/camera-validation.md) に分けて記録しています。実ブラウザでは写真選択からの自動送信、合否表示、カメラ上の他者通過通知、通信切断・復旧時のエラー保持を確認しました。実機のライブカメラ取得は未検証です。

## 検証・エビデンス更新

```sh
npm run check
npm test
# ローカルのデモ70接続・70画像・合格イベント
LOAD_CONNECTION_MODE=poll node scripts/load-test.mjs
# 公開版の実時間30秒開始・権限・部屋分離・合格イベント（デモ）
TARGET_BASE_URL=https://ai-karimono-race.ahwenu.chatgpt.site node scripts/public-smoke.mjs
# 公開版のデモ70接続（70件の有料AI呼び出しはしません）
TARGET_BASE_URL=https://ai-karimono-race.ahwenu.chatgpt.site LOAD_CONNECTION_MODE=poll LOAD_REPORT=docs/load-test-public.json node scripts/load-test.mjs
# 最新の保存記録から閲覧用レポートを再生成
node scripts/build-verification-report.mjs
```

- `docs/public-smoke.json`: 匿名の公開動作、実時間30秒の初回開始、部屋・権限分離、合格イベントの永続性。
- `docs/load-test-local.json` / `docs/load-test-public.json`: 約17MBの70画像集中投稿と確定イベント観測。最大8並列、デモ判定。
- `docs/real-image-verification.md` / `.json`: バナナ写真の実バイトをAPIへ送り、バナナOK・写っていない自動車NGを確認。
- `docs/boundary-image-verification.md` / `.json`: 実写真2枚で口元と服色を検証。曖昧例は事前に保留し、正解として数えません。
- `docs/public-reference-smoke.json`: 参考写真付きの公開実AI経路の最新結果。画像コピーと別の実物写真、参考写真の70同時取得、実ツール記録を含む場合があります。各項目と `success` を確認してください。
- `docs/public-ai-smoke.json` / `docs/public-prepare-ai.json`: 参考写真比較・初回自動開始の導入前の過去の実AI測定。現在のコピー防止の成功証拠には使いません。
- `/verification.html` / `/verification-data.json`: 写真、期待、返値、日時、出典を示す閲覧用・機械可読レポート。
- `scripts/sync-cloud-assets.mjs`: 生成したレポートと共通画面をSitesソースへ同期。

直接API検証の3枚・3リクエストは少数例です。公開経路の追加結果は別に記録し、一般的な精度、本人撮影、撮影時刻、実AI70件の同時性能を証明したとは扱いません。実レスポンスのレート上限は5,000 requests / 2,000,000 tokensでしたが、残量・予算・上流混雑によって実行可能量は変化します。

## Sites公開

`apps/cloud/.openai/hosting.json` がSite identityとDB / BUCKET bindingを保持します。D1 migrationとSitesの正規ソース同期・ビルド・保存・デプロイ手順を使います。詳細は `apps/cloud/README.md`。

公開版はMacを起動し続ける必要がなく、別ネットワークの端末も公開QRから参加できます。全員にインターネット接続が必要です。70枚×250KBなら約17.5MB、上限1MBなら70MBの会場上り通信が発生します。既存のローカルSQLiteデータは公開D1へ自動移行しません。
