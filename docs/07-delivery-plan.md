## 担当別の具体的な作業

### Akibako さん：デザイン

- P01〜P08の参加者画面を設計し、お題・残り時間・撮影・合否・順位の優先順位を定める。
- 色・文字サイズ・余白・ボタン・カードの共通仕様を用意する。
- 読込、カメラ拒否、送信中、判定不明、通信失敗、締切、次問待ちを含む状態別見本を作る。
- 03のpropsに沿った表示部品をmae さんへ渡す。API呼出・カメラ制御・採点処理は持たない。
- 共通トーンを拡張画面担当にも共有する。ホスト画面全体の実装は別担当とする。

### mae さん：参加者向けフロントエンド

- デザインをSitesのスマホ画面へ組み込み、コード入力・参加・待機・お題・結果までの遷移を実装する。
- カメラ許可、撮影、JPEG変換・圧縮、プレビュー、撮り直し、写真送信を実装する。
- AhwenuのHTTP APIに接続し、Cookieセッション、冪等キー、エラー表示を扱う。
- 部屋状態・順位のポーリング、残り時間表示、再読込・通信切断後の復帰を実装する。
- iPhone SafariとAndroid Chromeで、撮影から結果までを実機確認する。

### さが さん：バックエンド

- D1のテーブル、一意制約、マイグレーション、部屋・チーム・提出の永続化を実装する。
- 部屋作成・参加、開始・次問・終了、サーバー時刻による締切、試行回数と同時提出制限を実装する。
- AI判定結果を受け取って提出を確定し、二重加点防止・順位集計・遅延結果の排除を実装する。
- R2保存、画像検証・取得、保持期限・削除、部屋権限とセッションの発行・検証を実装する。
- Ahwenuから呼べるゲームサービスを提供し、DBの原子的更新・締切・認可・加点のテストを持つ。

### Ahwenu：APIの処理

現在の作業先は独立した `api/` と `plugin/src/server/`。Sitesは他担当が扱うため、既存 `apps/cloud/`、Sitesの配備設定、ゲームDBは今回のAPI接続作業で変更しない。[11 API連携](11-api-integration.md)の入出力と設定名を受け渡す。

- 04のHTTPエンドポイント、共有DTO、入力スキーマ、成功/エラー形式を定義・実装する。
- HTTP要求から認証情報を取り出し、さが さんの認可・ゲームサービスを呼び、結果をDTOへ変換する。
- 写真受付→保存サービス→外部AI判定→確定サービスというAPI処理をつなぐ。ルールや加点をAPI層に重複実装しない。
- Agents APIのお題生成、Decisions APIの画像判定、タイムアウト・再試行・費用上限・結果正規化を実装する。
- MCPサーバー、ホストツール、資格情報の安全な保管、Sites APIへのHTTP接続を実装する。
- mae さんと拡張画面担当へAPI/MCPモック・サンプル・接続手順を渡し、API結合テストを持つ。
- 完成版の参考写真サービスへの接続もAPI担当として実装する。

### Plugin Extensions画面：未定（Ahwenu）

- H01〜H04のホスト画面を拡張内に実装する。
- 部屋作成、参加用URL/QR、参加者一覧、最終通信、判定状況、ランキングを表示する。
- MCPブリッジから開始・次問・終了を呼び、二重操作や古い状態での操作を防ぐ。

- API処理担当のAhwenuが提供するMCP契約を使う。画面担当が正式決定するまでは、必要な画面と入出力の仕様を先に揃える。

## バックエンドとAPI処理の境界・受け渡し

| 作業 | 主担当 | 受け渡し・確認先 |
| --- | --- | --- |
| 画面・UI部品 | Akibako さん | mae さんへpropsと状態見本を渡す |
| HTTP契約・モック | Ahwenu | mae さん・さが さんと確認して固定 |
| ゲームサービスの関数契約 | さが さん | Ahwenuと引数・結果・失敗理由を合わせる |
| DB・R2・認可・冪等記録の永続化 | さが さん | AhwenuがAPIルートから利用する |
| HTTPヘッダー・Cookie・入力検証・エラー変換 | Ahwenu | さが さんの認証/認可サービスへ委譲する |
| AIへの要求・判定の正規化 | Ahwenu | さが さんへ合否・失敗コードを渡す |
| 締切・試行制限・加点・順位の確定 | さが さん | APIは確定結果を画面へ返す |
| MCPツール・Sites接続 | Ahwenu | 拡張画面担当へ秘密値を除いたDTOを渡す |
| 拡張のUI・ブリッジ・操作状態 | 未定（Ahwenu） | AhwenuのMCPツールに接続する |

処理の流れは「画面 → AhwenuのAPI層 → さが さんのゲーム/保存サービス」。外部AIが必要な箇所はAhwenuのアダプターを使い、その結果の採点・永続化はさが さんのサービスで確定する。

## 実装前に共有する契約

04のDTO・エラーコードはAhwenu、03のpropsはAkibako さんとmae さん、ゲームサービスの関数契約はさが さんとAhwenu、08のMCP入出力はAhwenuと拡張画面担当が先に合わせる。`contracts/` はAhwenuが初版を作成し、mae さん・さが さんが確認する。モックは同じスキーマから作る。

Akibako さんは状態別の画面見本を渡す。AhwenuはAPIサンプルと操作手順を用意し、さが さんのサービスやAIの完成前でもスキーマに一致するモックで結合できるようにする。

## 並行開発の進め方

パスごとの担当と共有設定の取りまとめは[09 フォルダ構成・デプロイ](09-repository-structure.md)を正本とする。デプロイの容易さを最優先に、Sitesとpluginの依存・ビルド・配布物を分ける。

- Akibako さんはcomponentsと画面見本、mae さんはfeaturesとSitesの参加者ページを中心に編集する。
- さが さんはdbとserver/game・auth・storage・repositories、Ahwenuはapp/api・contracts・server/http・integrations・plugin/src/serverを中心に編集する。
- plugin/src/uiは未定（Ahwenu）の担当範囲とし、mae さんの作業に含めない。
- 共有型はAhwenuが初版を作り、mae さん・さが さんが利用例で確認する。
- 小さい機能単位でブランチを分け、契約が変わる変更は関連画面と同じレビューで扱う。
- サーバー認可・API・DBが揃った順に、モックを実接続へ切り替える。
- プラグインの更新・配布物作成とSitesの配備は別工程。互換性を壊すDTO変更時は両方の対応版を合わせる。
- plugin/apiの依存・lock・起動設定はAhwenu、DBマイグレーションはさが さん、共通トークンとUI部品はAkibako さんが取りまとめる。Sitesの依存・配備設定はSites担当と調整し、並行した再生成や全体整形を避ける。

## 必須の検証

| 領域 | シナリオ | 期待結果 |
| --- | --- | --- |
| 得点 | 同じ送信を繰り返す、並行して合格結果が届く | 加点は1問1チーム10点まで |
| 時間 | 締切直前に受理、締切と同時/直後、端末時計を変更 | サーバー受付時刻で統一。締切以後を拒否 |
| 中断 | 判定中に切断、Workers処理停止、遅れてAI応答 | 期限で失敗確定、枠解放、遅延加点なし |
| 進行 | ホストが次問を二重押下、締切直後に次問 | 二重進行なし。closing中は拒否 |
| 認可 | 参加者が管理API、別部屋のID、他チーム画像を要求 | 全てサーバーで拒否 |
| モバイル | カメラ拒否、HEIC、回転、バックグラウンド復帰 | 説明と復帰導線、表示崩れなし |
| 拡張 | 再表示、MCP再起動、接続先ダウン、古いversionで操作 | 部屋復元、エラー表示、最新状態に同期 |
| AI | 正解・不正解・曖昧・文字による指示を含む画像 | 評価結果を記録。不明/通信失敗を合格にしない |
| 保存 | 期限切れ、削除後画像取得、ログ確認 | 画像アクセス拒否、秘密値が出力されない |

ゲームルール・認可・冪等性は自動テスト、カメラとPlugin Extensionsは実機/実アプリで確認する。最初はiPhone SafariとAndroid Chromeをそれぞれ最低1台用意する。

| 未決事項 | 現時点の初期案 | 決定タイミング |

## 開発・配布のルール

- 作業開始時に[ADR一覧](adr/README.md)と関連ADRを確認し、重要な方針決定・変更時は実装・仕様と同じ変更でADRを追加・更新する。Acceptedの方針を変更する場合は後継ADRを作り、旧判断の履歴を残す。
- MVP・完成版とも、参加者はスマホのブラウザで使う前提とする。
- 変更したスキーマ・API契約・画面状態は同じ変更で文書へ反映する。
- 現在はpluginの独立した画面/MCP骨格を実装する段階。Sites・モバイル・バックエンドのデモソースは[10](10-demo-import.md)の配置に取り込み済みだが、現在の仕様への適合、本環境での外部API接続・配備、拡張との実接続は未検証。プラグイン登録・実機結合も未完了として区別する。骨格の起動手順は[plugin/README.md](../plugin/README.md)を参照。
